# AI 对话进度接入

前端不推断固定阶段，不按时间生成结果。适配器在发送时读取 `window.JianxAppraisalService.run(request)`。请求包含 `photos`（本机预览 URL/name）、`text`、`skill`、`signal`、`onEvent`；服务负责按既定隐私授权处理图片与网络请求。当前静态工程未配置真实鉴定服务。

## 事件

- `step`：`id` 为稳定环节标识，`title/detail` 为适合用户阅读的简短状态，`status` 为 `active` 或 `done`，`technical` 为可选字符串或字符串数组。相同 id 原地合并，技术记录去重。新 active 环节接替前一个 active；已完成环节不被迟到的 active 重开。并行底层操作应归入一个用户可读的当前环节，不能用多个 active 表示同时运行。
- `heartbeat`：仅保持连接活跃，不产生新步骤。
- `progress`：`value` 为真实的 0–100 百分比，null 恢复不定进度；完成前最高显示99，明确完成后才可100。未知总工作量时不要发送百分比。
- `complete`：`result` 为非空文本，或 `{title, paragraphs: string[], rows: string[][]}`；rows 按点位、结论、符合度排列，所有内容按文本安全渲染。发送此事件才显示结论；空结果不视为完成。
- `error`：`message` 为公开错误，`retryable` 默认为 true；消息含代码时显示通用错误。取消/失败/完成为终态，之后事件均忽略。
- `eventId`：可选，用于跨重发去重。

`run` 可以同步启动流，也可以返回 Promise；Promise 返回有效结果等价于 complete，抛出/拒绝等价于 error。没有返回值不会触发自动完成，适配器必须最终发送 complete 或 error，且应在真实连接中断时发送 error。signal 取消后停止请求及回调。

每次重试创建新状态和取消信号，旧调用的迟到数据不会进入新任务。步骤摘要应由实际任务状态映射得到；不要透传模型内部推理、路径或代码。技术记录只接收可公开的脱敏操作日志，不能含凭据或私人数据，默认不放入可见 DOM。
